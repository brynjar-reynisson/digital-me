# Capture Google Docs via Screenshot OCR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `scripts/screenshot-capture.py` recognize an open Google Doc as a fourth capturable site (alongside LinkedIn/Facebook/Quora), OCR its content, and index it via `/addContent` — while skipping the Google Docs homepage/file-picker and discarding the Chrome extension's redundant (near-empty, canvas-rendered) capture of the same URL server-side.

**Architecture:** `SITE_KEYWORDS` gets a `"google docs"` entry so `detect_site()` recognizes the window title. A new pure function, `is_non_document_google_docs_page(pagename, url)`, filters out the homepage/file-picker when the address-bar URL is readable (Chrome/Edge) and doesn't contain `/document/d/`; when the URL can't be read, capture falls back to title-only (same graceful-degradation shape already used for `SUBPAGE_GATED_SITES`). `CROP_CONTENT_SITES` gets `"google-docs"` added so the existing UIA landmark-cropping is attempted (with its existing full-fallback chain). Server-side, `ScreenshotCoverage.isCovered()` gets an unconditional `docs.google.com` check (mirroring `facebook.com`) so the Chrome extension's own capture of the same URL is discarded.

**Tech Stack:** Python (existing `screenshot-capture.py` toolchain, no new dependencies), Java 19 / JUnit 5 (existing project stack, no new dependencies).

## Global Constraints

- No FileChangeWatcher changes — the original `.gdoc`-file-watching idea is dropped entirely (Drive for Desktop's virtual drive blocks all raw reads of `.gdoc` placeholders; confirmed empirically, see `docs/superpowers/specs/2026-07-17-read-gdoc-design.md`).
- No Google Sheets/Slides support — Docs only.
- No Google API/OAuth integration of any kind.
- No backfill of documents visited before this ships — forward-looking only.
- `SITE_KEYWORDS` gets exactly `"google docs": "google-docs"` (lowercase key, matches `detect_site()`'s `.lower()` substring check; pagename value `"google-docs"` matches `CROP_CONTENT_SITES`'s existing hyphenated style, e.g. `"linkedin"`, not `"linkedin.com"`).
- Document-vs-homepage regex: `GOOGLE_DOCS_DOCUMENT_PATTERN = re.compile(r"docs\.google\.com/document/d/")`.
- `ScreenshotCoverage.isCovered()`'s `docs.google.com` check is unconditional (no subpath gating), mirroring `facebook.com` exactly — not gated like `linkedin.com`/`quora.com`.
- New pure functions are duplicated (not imported) into `scripts/test_screenshot_logic.py`, matching that file's existing convention (it inlines its own copies rather than importing the hyphenated `screenshot-capture.py` filename).
- Python tests run via `cd scripts && python -m pytest test_screenshot_logic.py -v` (per prior plans' established convention).
- Java tests run via `cmd //c "C:\Program Files\JetBrains\IntelliJ IDEA Community Edition 2023.3.5\plugins\maven\lib\maven3\bin\mvn.cmd" test -Dtest=<TestClass>` (per `docs/tooling.md` — `mvn` is not on PATH).
- Full rationale: `docs/superpowers/specs/2026-07-17-read-gdoc-design.md`.
